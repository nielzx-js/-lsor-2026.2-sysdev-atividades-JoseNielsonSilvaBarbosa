### Passo 4 — Definindo Donos e Permissões das Pastas

Neste passo verifico as permissões iniciais (pertencentes ao `root`), transfiro a posse recursiva das pastas para o usuário `administrador` e para os respectivos grupos departamentais com `chown -R`, e aplico a permissão `770` com `chmod -R` para bloquear qualquer acesso de outros usuários.

Rodei os comandos de verificação inicial, alteração de posse/permissão e validação final e obtive:
```bash

sudo chown -R administrador:vendas-group vendas-dept

```

A saída final do `ls -ld` mostra `drwxrwx---` com dono `administrador` e os grupos `ti-group` e `vendas-group`, confirmando que dono e grupo têm controle total e outros usuários não têm acesso.

### Passo 5 — Criando um Arquivo Confidencial

Neste passo crio o arquivo `arquitetura_rede.txt` dentro de `ti-dept/projetos/`, defino `administrador` como dono e `ti-group` como grupo, e aplico a permissão octal `660` para permitir leitura e escrita apenas ao dono e ao grupo.

Rodei os comandos para criar e configurar o arquivo confidencial e obtive:

### Desafio de Laboratório — Departamento da Diretoria (`diretoria-dept`)

Neste desafio crio a estrutura isolada para a diretoria (`/srv/diretoria-dept` e `diretoria-group`), associo o usuário `beltrano`, aplico a permissão `770` na pasta e `660` no arquivo `orcamento.txt`, e valido o acesso permitido para `beltrano` e bloqueado para `fulano`.

Rodei os comandos de criação e configuração do desafio e obtive:

```bash
sudo touch /srv/diretoria-dept/orcamento.txt
sudo chown administrador:diretoria-group /srv/diretoria-dept/orcamento.txt
sudo chmod 660 /srv/diretoria-dept/orcamento.txt
ls -ld /srv/diretoria-dept
ls -l /srv/diretoria-dept/orcamento.txt
```

A saída mostra a pasta `/srv/diretoria-dept` com `drwxrwx---` e o arquivo `orcamento.txt` com `-rw-rw----`, ambos pertencentes a `administrador:diretoria-group`.

### Tabela de Comandos da Aula

| Comando | O que significa / o que faz |
|---|---|
| `cd /etc` | Altera o diretório atual de trabalho para `/etc` (pasta de configurações do sistema). |
| `pwd` | Exibe o caminho completo do diretório atual onde o usuário está posicionado (*Print Working Directory*). |
| `ls -F`, `ls -R`, `ls -ld` | Lista arquivos e pastas: `-F` adiciona `/` ao final de diretórios; `-R` lista subdiretórios recursivamente; `-ld` exibe detalhes e permissões do próprio diretório sem listar seu conteúdo. |
| `sudo tail -n 10 /var/log/auth.log` | Exibe com privilégios de administrador as últimas 10 linhas do arquivo de log de autenticação do sistema. |
| `mkdir -p` | Cria diretórios e toda a árvore de pastas intermediárias ("mães") necessárias de uma só vez, sem gerar erro caso já existam. |
| `groupadd` | Cria um novo grupo de usuários no sistema (registrado em `/etc/group`). |
| `usermod -aG` | Adiciona (`-a`, *append*) um usuário a um ou mais grupos secundários (`-G`) sem removê-lo dos grupos aos quais já pertence. |
| `id` | Exibe o UID (identificador do usuário), o GID (grupo principal) e todos os grupos secundários de um usuário. |
| `chown -R dono:grupo` | Altera recursivamente (`-R`) o usuário proprietário e o grupo dono de um diretório e de todo o seu conteúdo. |
| `chmod 770 / chmod 660` | Altera as permissões de acesso usando notação octal: `770` (`rwxrwx---`) dá controle total ao dono e grupo em pastas; `660` (`rw-rw----`) dá leitura e escrita ao dono e grupo em arquivos, bloqueando outros usuários em ambos os casos. |
| `touch` | Cria um arquivo vazio ou atualiza a data/hora de modificação de um arquivo existente. |
| `su -` x `su` | Troca de usuário no terminal: `su` mantém o diretório e as variáveis de ambiente do usuário anterior; `su -` simula um login completo, indo para o `/home` do novo usuário e carregando suas variáveis e configurações. |
| `whoami` | Exibe o nome do usuário efetivamente ativo na sessão atual do terminal. |

## 6. Problemas e Soluções

Um problema comum nesta prática ocorre quando um usuário já estava logado em outra sessão antes de ser adicionado a um novo grupo com `usermod -aG` e recebe `Permission denied` ao tentar acessar a pasta do departamento, ou quando se utiliza `su` sem o hífen (`su fulano`), mantendo as variáveis de ambiente do usuário anterior.

Para resolver o problema de atualização de grupo, é necessário encerrar a sessão do usuário com `exit` e realizar um novo login completo com `su - <usuario>`, conferindo a atualização dos grupos com o comando `id`. Além disso, comandos que alteram diretórios em `/srv` ou configurações do sistema exigem o prefixo `sudo` quando executados pelo usuário `administrador`.

## 7. Conclusão

Separar diretórios por departamento e aplicar permissões restritas (`770` para pastas e `660` para arquivos) é fundamental para a segurança e confidencialidade em um servidor Linux multiusuário. Esse modelo garante o princípio do menor privilégio, assegurando que cada equipe acesse e modifique apenas os dados pertinentes à sua função, enquanto usuários não autorizados ou de outros setores são bloqueados pelo próprio sistema operacional.
